# 年龄分级（幼童 / 儿童 / 成人）功能设计——概念研究

**性质**：概念研究文档，非 Happy 特性设计，不含实现约束。
**日期**：2026-07-28
**命题**：面向不同年龄用户的分级使用，应体现为哪些功能设计差异？这些差异的依据是什么？

---

## 1. 背景与范围

本文源于对 Happy 是否具备年龄分级功能的核查。已确认 Happy 本体与整个 Claude Code
插件/agent/skill 生态均无此类功能（见 `docs/reports/age-tiering-feature-audit.md`）。
本文不为 Happy 立项，而是把「按年龄分级」作为一个通用产品设计命题独立研究，Happy 仅作为思考起点。

**范围声明**：
- 讨论的是「产品内按年龄分级的使用逻辑」，不是应用商店提交时填写的年龄分级元数据。
- 三档（幼童/儿童/成人）的边界是**模糊且随场景滑动**的——同一个 12 岁孩子，在阅读能力上接近成人、
  在冲动控制上仍是儿童。分档是设计上的锚点，不是非黑即白的开关。
- 结论以「AI 对话 / LLM 类产品」为主要落地想象（见 §6），但 §2–§5 的原则对多数面向儿童的数字产品通用。

---

## 2. 年龄分档定义

| 档位 | 年龄（约） | 发展锚点 | 对应法规阈值 |
|------|-----------|---------|-------------|
| **幼童** | 3–5 | 前识字期；语言萌芽；粗大动作为主，精细动作弱；前运算认知（具象、自我中心） | 中国指南 <3 / 3–8 段 |
| **儿童** | 6–12 | 学龄；识字发展中；具体运算认知（能逻辑推理但需具体情境）；规则意识形成 | COPPA <13；中国指南 8–12 段 |
| **成人** | 13+ | 形式运算认知（抽象/假设推理）；完整识字与操作能力 | GDPR-K 13–16 为数字同意年龄；AADC 仍保护至 18 |

> 说明：13 岁是多数隐私法（COPPA、部分 GDPR 成员国）的分界，但英国 AADC 把「儿童」保护延伸到 18 岁，
> 因此「成人」在合规意义上往往指 18+，「13–17」是一个需要弱化保护但仍非完全放开的过渡带。本文为聚焦
> 三档，把 13+ 归入「成人」处理，实际产品应视监管辖区再细分青少年带。

## 3. 依据框架：三支柱

任何一条分级设计差异，最终都能归因到以下三根支柱之一。三者的分工是：
**发展心理学决定「用户能理解/操作到什么程度」，法规决定「必须默认保护什么」，CCI 决定「界面怎么做才安全好用」。**

### 3.1 发展心理学 → 决定 模态 / 复杂度 / 节奏
- **Piaget 认知阶段**：前运算期（2–7，具象、缺乏抽象与守恒概念）→ 具体运算期（7–11，能逻辑推理但依赖具体事物）→ 形式运算期（11+，抽象与假设推理）。这直接约束内容复杂度与解释方式。
- **识字发展**：幼童为前识字期，界面不能依赖文字；儿童识字发展中，需简化词汇与图文并茂；成人可承载高密度文本。
- **精细动作**：幼童手指控制粗糙 → 需超大点击目标（Fitts 定律在儿童 HCI 中的体现）。
- **注意力时长**：随年龄增长，直接决定单次会话时长与是否需要强制休息/节奏控制。

### 3.2 法规合规 → 决定 数据 / 安全 / 家长同意 / 时长（硬约束）
- **美国 COPPA**：覆盖 <13。2025-04 修订、2025-06-23 生效、2026-04-22 合规；要求可验证的家长同意、数据最小化；新版把生物识别（指纹/人脸）与政府标识纳入受保护个人信息，并承认人脸识别匹配为一种验证方式。
- **欧盟 GDPR-K（第 8 条）**：数字同意年龄 13–16（各成员国自定），低于该龄需家长同意。
- **英国 AADC（儿童准则 / Children's Code）**：覆盖 <18，15 项标准，核心为 privacy-by-default、data minimization、no nudging（禁诱导）；由 ICO 强制执行，2026 计划扩展到手游并联合 Ofcom 发布年龄保证指引。
- **中国《移动互联网未成年人模式建设指南》（2024-11）**：分龄内容推荐（<3 亲子音频启蒙 / 3–8 启蒙与兴趣 / 8–12 常识科普正向娱乐）；每日总时长上限（<16 岁约 1 小时量级）；22:00–06:00 时段限制（家长可豁免）；连续使用 30 分钟提示休息。
- **应用商店分级**：IARC / ESRB / PEGI 提供内容适龄标注体系。

### 3.3 儿童-计算机交互（CCI）→ 决定 UI 机制
- 大点击目标、voice-first（前识字期）、safety-by-default（默认最严，而非默认开放再收紧）、无死胡同的错误处理（永远有下一步、不指责）、拒绝驱动沉迷的游戏化。

## 4. 分档功能设计差异（主体）

七个维度，每维给出三档做法，并回指所依据的支柱。

### 4.1 输入 / 输出模态 —（依据：发展心理学 §3.1 + CCI §3.3）
- **幼童**：语音 + 图标 + 超大点击区，**零文字输入**；输出以语音/图像/动画为主（前识字期无法读写）。
- **儿童**：简化文字 + 图文混合；可慢速打字；关键操作仍保留图标冗余。
- **成人**：全文本、高信息密度、键盘快捷键、多步复杂流程。

### 4.2 内容边界与过滤 —（依据：法规 §3.2 + CCI safety-by-default）
- **幼童**：围墙花园 / 白名单，绝不暴露未过滤的开放式生成内容或开放联网。
- **儿童**：分类过滤 + 事后可审核；受限、可控的联网。
- **成人**：开放、无限制。

### 4.3 认知 / 语言复杂度 —（依据：发展心理学 Piaget §3.1）
- **幼童**：单一具体概念、重复、即时反馈与奖励；不引入抽象或假设。
- **儿童**：有脚手架的简单解释、循序渐进、可给具体例子。
- **成人**：完整复杂度、抽象与多层逻辑。

### 4.4 家长监护 —（依据：法规家长同意 §3.2 + 发展自主权梯度）
- **幼童**：全托管——家长是唯一操作者/守门人，儿童在家长在场下使用。
- **儿童**：家长仪表盘 + 审批流 + 使用报告；孩子有一定自主但重要动作需批准。
- **成人**：无监护，自管。

### 4.5 时长与节奏 —（依据：法规时长条款 §3.2 + 注意力发展 §3.1）
- **幼童**：极短会话 + 强制休息；总量严格（参考 AAP 对 2–5 岁 ≤1h/天 的屏幕时间指引）。
- **儿童**：每日上限 + 休息提醒（呼应中国指南 30 分钟提示、宵禁时段）。
- **成人**：无限制。

### 4.6 隐私 / 数据 —（依据：法规 COPPA/GDPR-K/AADC §3.2）
- **幼童**：数据最小化、无行为追踪、无个性化广告；需**可验证的家长同意**。
- **儿童**：最小化 + 家长同意；高隐私默认。
- **成人**：标准数据实践。

### 4.7 视觉情感与防沉迷 —（依据：CCI + AADC no-nudging §3.2/3.3）
- **幼童**：明亮、角色化、动画、游戏化——**但禁止**利用儿童认知弱点的诱导式暗黑模式。
- **儿童**：成就/进度激励，但不制造 FOMO 或连续登录压力。
- **成人**：中性、专业、信息导向。

## 5. 前置能力：年龄识别（Age Assurance）

所有分级的地基是「先知道用户属于哪一档」。没有它，分级只是自欺。

- **手段谱系**：自声明年龄门（最弱）→ 家长账号绑定 → 硬性身份/年龄验证 → 年龄估计（人脸/行为，最强也最具隐私争议）。
- **法规期待**：AADC 要求以「与风险相称的适当确定性」确认年龄；COPPA 2025 承认人脸识别匹配为验证方式之一。
- **张力**：越强的年龄确认越侵犯隐私，本身与「对儿童数据最小化」冲突——需按产品风险等级选择相称手段，而非一律采集生物特征。
- **设计原则**：无法确定年龄时，**默认按最严档（幼童/儿童）对待**，而非默认成人（safety-by-default 的直接推论）。

## 6. 应用到 AI 对话 / LLM 产品的具体含义

命题源于 Claude Code / LLM 场景，故单列一节说明三档在 AI 对话产品中的落地映射：

| 面向 | 幼童 | 儿童 | 成人 |
|------|------|------|------|
| **输出审核强度** | 最严；仅白名单主题；任何越界一律安全兜底 | 分类过滤 + 可审核；敏感话题转家长/教育口径 | 标准安全策略 |
| **system prompt 约束** | 强人格化、极简词汇、绝不涉危险/成人主题、鼓励为主 | 教育者口吻、循序渐进、可解释「为什么不能」 | 无特殊约束 |
| **拒答行为** | 不解释拒答细节，直接转向安全替代（无死胡同） | 温和解释 + 引导到合适资源 | 标准拒答 |
| **输出模态** | TTS / 语音优先（前识字期）+ 图像 | 文字 + 朗读可选 | 纯文本 |
| **联网 / 工具** | 关闭开放联网与任意工具调用 | 白名单工具、受控检索 | 开放 |
| **记忆 / 个性化** | 不做持久画像 | 最小化、家长可见可清除 | 标准 |

要点：对 AI 产品而言，分级的重心从「界面」前移到「**模型行为的约束层**」——同一个底座模型，通过
系统提示、审核管线、工具白名单、输出模态四处闸门，呈现出三种截然不同的产品人格。

## 7. 横切原则与反模式

**贯穿三档的原则**：
- safety-by-default：不确定就从严，而非从宽。
- 数据最小化：能不采就不采，尤其是低龄档。
- 无诱导（no nudging / no dark patterns）：不利用儿童认知弱点驱动使用时长或消费。

**反模式与风险**：
- **谎报年龄**：自声明年龄门形同虚设 → 需与风险相称的年龄保证，且默认从严兜底。
- **过度游戏化致沉迷**：游戏化提升幼童参与度，但越界即成 AADC 明令禁止的 nudging；奖励应服务学习目标而非留存指标。
- **家长监护 vs 儿童自主权的张力**：监护过重压制发展中的自主性，过轻则失去保护意义；随档位上移应让渡更多自主（见 §4.4 梯度）。
- **年龄保证 vs 隐私的悖论**：越强的年龄确认越采集敏感数据，与数据最小化冲突（见 §5）。

## 8. 设计决策速查表

一页式「维度 × 三档」快查矩阵，供后续任意产品直接取用。

| 维度 | 幼童（3–5） | 儿童（6–12） | 成人（13+） |
|------|-----------|-------------|------------|
| 输入模态 | 语音+图标+大按钮，零文字 | 简化文字+图文 | 全文本+键盘 |
| 输出模态 | 语音/图像/动画 | 文字+可选朗读 | 纯文本高密度 |
| 内容边界 | 围墙花园/白名单 | 过滤+可审核 | 开放 |
| 认知复杂度 | 单一具体+即时反馈 | 脚手架+循序渐进 | 完整复杂度 |
| 家长监护 | 全托管 | 仪表盘+审批 | 无 |
| 时长节奏 | 极短+强制休息 | 上限+休息提醒 | 无限制 |
| 隐私数据 | 最小化+家长同意 | 最小化+家长同意 | 标准 |
| 视觉/防沉迷 | 游戏化但禁诱导 | 成就激励 | 中性专业 |
| 年龄识别 | 默认最严兜底 | 家长绑定 | 自声明即可 |
| （AI）模型约束 | 强约束+安全兜底 | 教育口吻+可解释 | 标准 |
